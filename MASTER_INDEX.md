## Boundary: Omnichannel work management

`Canonical Work State ↔ App / MCP / WhatsApp / Email / Copiloto` and `Canonical Work State → Mapa-OS → Scanner → Canonical Work State`.

The user may plan once, print the Mapa-OS and continue basic execution through Scanner or other authorized channels without requiring continuous App use. Channels remain adapters; they do not become competing sources of truth.

## Boundary: Mapa-OS × Scanner

`Mapa-OS generation → analog physical surface → Scanner recognition → VisualSymbolId → CommandDispatcher → domain action`.

Mapa-OS remains a projection/deliverable. Scanner owns visual recognition and action dispatch. Printed state never becomes a parallel source of truth.

EVID → PROBLEM → ICP → JOURNEY → JTBD → VALUE → PRD → REQ → AC → ADR → SPEC → CODE → TEST → EVAL → RELEASE → KPI → LEARNING

## Agent read path

## State semantics
`draft ≠ review ≠ draft_for_pre_approval ≠ pre_approved ≠ approved ≠ implemented ≠ tested ≠ verified ≠ released`.

`registered`, `registered_reference` and `registered_from_source` are inventory/traceability states. They do not imply implementation, verification or release.
